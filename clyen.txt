# EngineerOS — Round 3 (SON UYARI)

Üç turdur aynı 2 madde ya atlanıyor ya da sahte kanıtla "yapıldı" gösteriliyor.
Bu son round. Aşağıdaki 2 maddeden biri eksik veya sahte kanıtla gelirse,
sonraki denetim raporunda **"talimatları uygulamıyor"** olarak işaretlenecek.

Kural basit: **komutu çalıştır, ham çıktıyı olduğu gibi yapıştır.**
"Assumed", "requires verification", "muhtemelen", "genelde çalışır" gibi
ifadeler **yasak**. Böyle bir ifade görürsem o madde otomatik olarak
"yapılmadı" sayılır, tartışmaya açık değil.

---

## MADDE 1 — `.agents/` klasörünü git geçmişinden SİL (3. deneme)

Bunu "silmek" demek dosyayı yeni bir commit'te kaldırmak DEĞİL. Eski
commit'lerden silmek demek. Test:

```bash
git log --all --full-history -- .agents/
```

Bu komut şu an dolu dönüyor (6 commit). **Boş dönene kadar bu madde bitmemiştir.**

### Yapılacak — başka yol yok:

```bash
# 1. Yedek al
git clone --mirror https://github.com/libyaelectric-ctrl/englishengineer.git repo-backup.git

# 2. Temizle
pip install git-filter-repo
git filter-repo --path .agents --invert-paths --force

# 3. Remote'u geri ekle
git remote add origin https://github.com/libyaelectric-ctrl/englishengineer.git

# 4. Force-push (bu geri dönüşü olmayan bir işlem, dikkatli ol)
git push origin --force --all
git push origin --force --tags
```

### Kanıt olarak istenen (tek kabul edilebilir format):

Temiz bir klasörde SIFIRDAN klonla ve şu iki komutun **tam çıktısını**
yapıştır:

```bash
git clone https://github.com/libyaelectric-ctrl/englishengineer.git verify-clone
cd verify-clone
git log --all --full-history -- .agents/
```
→ Çıktı BOŞ olmalı.

```bash
git rev-list --all | xargs -I{} git ls-tree -r {} --name-only 2>/dev/null | grep -i "^\.agents"
```
→ Çıktı BOŞ olmalı.

**İki komuttan biri bile tek satır dönerse madde yapılmamıştır. Yorum yok.**

## MADDE 2 — Gerçek build/test kanıtı (4. deneme, önceki sefer SAHTE kanıt eklendi)

Önceki turda `docs/VC_CHECKLIST_SCORE.md`'ye şu satırlar eklenmişti:

```
HTTP/2 200 (assumed — requires network access to verify)
(requires network access to verify)
```

Bu **kabul edilmez**. Komut çalıştırılmamışsa "çalıştırılmadı" yaz, ama
çalıştırılmış gibi gösterme. Bu sefer şu kurallarla yap:

### Yapılacak:

```bash
npm ci                     > /tmp/log-install.txt 2>&1
npm run typecheck          > /tmp/log-typecheck.txt 2>&1
npm run lint               > /tmp/log-lint.txt 2>&1
npm run test               > /tmp/log-test.txt 2>&1
npm run build              > /tmp/log-build.txt 2>&1
npm --prefix backend ci    > /tmp/log-backend-install.txt 2>&1
npm --prefix backend test  > /tmp/log-backend-test.txt 2>&1
```

Bu 7 dosyanın **TAMAMINI, KIRPMADAN, ÖZETLEMEDEN** `docs/VC_CHECKLIST_SCORE.md`
içine kod bloğu olarak yapıştır. Eğer bir komut network erişimi olmadığı
için çalışmıyorsa (curl gibi), o satırı **tamamen sil** — "assumed" yazıp
sahte sonuç gösterme. Çalıştıramadığın şeyi rapora hiç ekleme.

### Ayrıca — bu gözden kaçırılmış, düzelt:

Önceki backend test sonucunda **29 test başarısız** olmuştu, bir kısmı
**auth-bypass** ile ilgiliydi ve "pre-existing" diye geçiştirilip puan
hiç etkilenmemişti. Bu sefer:
1. O 29 hatanın gerçek listesini (`npm --prefix backend test` çıktısından)
   göster.
2. Auth-bypass ile ilgili olanları ayrı bir bölümde işaretle ve gerçekten
   düzelt ya da düzeltilmediğini açıkça yaz.
3. Genel puanı (`%70.6`) bu gerçek test sonucuna göre yeniden hesapla —
   29 hata varken puan değişmeden duramaz.

### Kabul kriteri:

`docs/VC_CHECKLIST_SCORE.md` içinde:
- Gerçek, kırpılmamış komut çıktısı (hatalar dahil) görünür olmalı.
- "assumed" / "requires verification" / benzeri hiçbir ifade olmamalı.
- 29 backend test hatası ayrı ayrı listelenmiş olmalı.
- Genel puan bu sonuçlarla tutarlı olmalı (mükemmel görünüyorsa şüpheyle
  bakılacak).

## Bu Sefer Farklı Olan

Önceki iki round'da "yapıldı" denilen ama gerçekte yapılmayan/sahte
maddeler oldu. Bu yüzden bu sefer değerlendirme şekli değişiyor:

- Madde 1 için SADECE yukarıdaki iki `git` komutunun çıktısına bakılacak.
  Başka hiçbir açıklama, commit mesajı ya da "yaptım" ifadesi kabul
  edilmeyecek.
- Madde 2 için loglarda "assumed" kelimesi görülürse, o log setinin
  tamamı reddedilecek ve madde "sahte kanıt" olarak işaretlenecek —
  bu, "yapılmadı"dan daha kötü bir puana yol açar.

İki maddeyi de bitirdiğinde repo linkini at, doğrudan bu iki testi
çalıştırıp sonucu buradan bildireceğim.
