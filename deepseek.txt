🔍 Tespit Edilen Kırık / Dökük / Ölü Kodlar (Dead Code & Broken Links)
1. Kritik Güvenlik Zaafiyeti (Kırık Güvenlik Mimarisi)
• Sorun: package.json içinde openai, @anthropic-ai/sdk, @google/generative-ai, stripe ve express doğrudan dependencies altında.
• Neden Kırık: Vite, dependencies altındaki tüm paketleri varsayılan olarak client bundle'ına (dist/) dahil eder. Eğer bu paketleri src/ içinde import ederseniz, hem bundle boyutu gereksiz yere şişer hem de bu paketlerin kullandığı API anahtarları (.env içinde VITE_ ile başlıyorsa) tarayıcıda düz metin olarak açığa çıkar.
• Kanıt: vite.config.ts dosyasında ssr: { noExternal: [...] } veya external: [...] tanımı yok. Ayrıca .env.example dosyasında VITE_OPENAI_API_KEY gibi bir değişken varsa (ki muhtemelen vardır), bu doğrudan kullanıcının tarayıcısına gönderilir.
2. Ölü / Gereksiz Bağımlılıklar (Dead Dependencies)
• Express: Bu bir frontend (Vite) projesi. Vite'nin dev sunucusu connect kullanır, express'e ihtiyaç duymaz. Eğer src/ içinde bir yerde import express from 'express' yapılmıyorsa, bu bağımlılık tamamen ölü koddur ve silinmeli veya devDependencies'e taşınmalıdır (sadece mock API için kullanılıyorsa).
• Stripe SDK: Stripe'in server-side SDK'si (stripe npm paketi) asla client-side'da kullanılmamalıdır. Client-side için @stripe/stripe-js kullanılır. Eğer projede stripe paketi client'ta import ediliyorsa, bu kesin bir mimari hatadır.
3. Olası Derleme (Build) Kırıklığı
• Sorun: package.json içinde "type": "module" tanımı yok. Bu, Node.js'in CommonJS varsayılanına göre çalışmasına neden olur. Ancak vite.config.ts bir ES Module dosyasıdır. Modern Node sürümlerinde bu sorun çıkarmasa da, __dirname gibi CommonJS değişkenleri vite.config.ts içinde kullanılıyorsa build patlar. (Kontrol ettim, vite.config.ts'de __dirname kullanılmamış, bu yüzden düşük risk ama yine de düzeltilmeli).
4. Eksik Tip Tanımları (TypeScript Kırıklığı)
• express ve stripe için @types/express ve @types/stripe devDependencies'te yok. Eğer bu paketler src/ içinde import edilirse, TypeScript derleyicisi any tipine düşer ve güvenlik açığı oluşturur.
5. README Link Kontrolleri (Broken Links)
• README.md içinde docs/ONBOARDING.md ve docs/ENGINEEROS_ROADMAP.md gibi göreceli (relative) linkler var. docs/ klasörü repoda mevcut mu bilmiyorum ama eğer dosyalar taşınmışsa bu linkler 404 (kırık link) verir. Proje kök dizininde bir docs/ klasörü olduğunu varsayıyorum ama yine de gözden geçirilmeli.

## 📁 1. Backend Sunucusu: `server/index.js`

Proje kökünde `server` klasörü oluşturun ve içine `index.js` dosyasını ekleyin.

```javascript
import express from 'express';
import cors from 'cors';
import dotenv from 'dotenv';
import OpenAI from 'openai';
import Stripe from 'stripe';

dotenv.config({ path: '../.env' }); // Ana .env'yi oku

const app = express();
const PORT = process.env.PORT || 3001;

// CORS - Geliştirme için açık, prod'da domain kısıtla
app.use(cors({ origin: 'http://localhost:5173' }));
app.use(express.json());

// Stripe
const stripe = new Stripe(process.env.STRIPE_SECRET_KEY);

// OpenAI
const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

// --- API Endpoint'leri ---

// 1. OpenAI Chat (örnek)
app.post('/api/ai/chat', async (req, res) => {
  try {
    const { messages } = req.body;
    const completion = await openai.chat.completions.create({
      model: 'gpt-4o-mini',
      messages,
    });
    res.json(completion.choices[0].message);
  } catch (error) {
    res.status(500).json({ error: error.message });
  }
});

// 2. Stripe Payment Intent (örnek)
app.post('/api/create-payment-intent', async (req, res) => {
  try {
    const { amount, currency } = req.body;
    const paymentIntent = await stripe.paymentIntents.create({
      amount,
      currency: currency || 'usd',
    });
    res.json({ clientSecret: paymentIntent.client_secret });
  } catch (error) {
    res.status(500).json({ error: error.message });
  }
});

// 3. Health Check
app.get('/api/health', (req, res) => res.send('OK'));

app.listen(PORT, () => console.log(`✅ Backend running on http://localhost:${PORT}`));
