## MADDE 1 (EN KRİTİK) — `.agents/` klasörünü git geçmişinden gerçekten sil

- **Round 1'de ne yapıldı, neden yetersiz:** Klasör sadece bir sonraki
  commit'te çalışma dizininden silindi. Ama `git log --all -- .agents/`
  hâlâ eski commit'leri listeliyor ve `git show <eski-commit>:.agents/skills/engineeros-deploy/SKILL.md`
  dosyanın tam içeriğini (gerçek Supabase proje URL'si, Vercel proje ID'si,
  Upstash URL'si) hâlâ eksiksiz geri veriyor. Yani "silme" commit'i sadece
  görünürlüğü kapattı, veriyi kaldırmadı.
- **Yapılacak (adım adım):**
  1. Repo'nun **tam bir yedeğini** al (bare clone): 
     `git clone --mirror https://github.com/libyaelectric-ctrl/englishengineer.git repo-backup.git`
  2. `git-filter-repo` kur (yoksa `pip install git-filter-repo`).
  3. Ana çalışma kopyasında çalıştır:
     ```bash
     git filter-repo --path .agents --invert-paths --force
     ```
  4. Remote'u tekrar ekle (filter-repo remote'u siler):
     ```bash
     git remote add origin https://github.com/libyaelectric-ctrl/englishengineer.git
     ```
  5. Force-push:
     ```bash
     git push origin --force --all
     git push origin --force --tags
     ```
  6. GitHub tarafında eski commit referanslarının önbellekte kalmaması için
     GitHub Support'a "cache purge" talebi gerekmeyebilir ama en az 90 gün
     boyunca eski SHA'ların GitHub'ın iç sistemlerinde (fork'lar, PR'lar,
     Actions cache) yaşayabileceğini unutma — bu yüzden anahtar rotasyonu
     (zaten yapıldı) bu adımın **yerine geçmiyor, tamamlayıcısı**.
  7. Herkesin (varsa diğer collaborator'lar) repoyu **yeniden klonlaması**
     gerektiğini bir README notu veya commit mesajıyla belirt — eski local
     kopyalar push ederse dosya geri gelebilir.
- **Kabul kriteri (bunu bizzat çalıştır ve sonucu yapıştır):**
  ```bash
  git clone https://github.com/libyaelectric-ctrl/englishengineer.git test-clone
  cd test-clone
  git log --all --full-history -- .agents/
  # Çıktı TAMAMEN BOŞ olmalı
  git rev-list --all | xargs -I{} git ls-tree -r {} --name-only 2>/dev/null | grep -i "^\.agents" | sort -u
  # Çıktı TAMAMEN BOŞ olmalı
  ```
  İkisi de boş dönmezse madde çözülmemiş demektir, tekrar dene.

## MADDE 2 — Case-mismatch linklerini TEK standarda göre düzelt

- **Round 1'de ne yapıldı, neden yetersiz:** `DEPLOYMENT.md` referansı
  `docs/DEPLOYMENT.md`'ye "düzeltildi" ama gerçek dosya hâlâ küçük harfle
  `docs/deployment.md`. Üç dosyada (`README.md`, `docs/README.md`,
  `docs/ONBOARDING.md`) hâlâ büyük harfli, kırık referans var.
- **Yapılacak (birini seç, ikisini birden yapma):**
  - **Seçenek A (önerilen):** `docs/deployment.md` dosyasını
    `docs/DEPLOYMENT.md` olarak yeniden adlandır (git üzerinde
    `git mv docs/deployment.md docs/DEPLOYMENT.md` kullan — sadece
    dosya sistemi rename değil, git rename olarak kaydedilsin).
  - **Seçenek B:** Dosyayı `docs/deployment.md` bırak, üç referansın
    üçünü de küçük harfe çevir.
- **Yapılacak (hangi seçeneği seçersen seç):**
  ```bash
  grep -rn "DEPLOYMENT.md" --include="*.md" .
  ```
  komutunun döndürdüğü HER satırdaki dosya adı, gerçek dosya adıyla
  (büyük/küçük harf dahil) birebir aynı olmalı.
- **Kabul kriteri:**
  ```bash
  # Seçtiğin standart neyse, gerçek dosya adını buraya yaz ve kontrol et:
  test -f docs/DEPLOYMENT.md && echo OK || echo FAIL   # (Seçenek A ise)
  grep -rn "deployment.md\|DEPLOYMENT.md" --include="*.md" . | grep -v "docs/DEPLOYMENT.md"
  # Bu ikinci komut BOŞ dönmeli (yani tutarsız case kalmamış olmalı)
  ```

## MADDE 3 — `docs/VC_CHECKLIST_SCORE.md` içindeki taşınmış dosya referanslarını güncelle

- **Round 1'de ne yapıldı, neden yetersiz:** `docs/` sadeleştirilirken
  (Round 1 madde 3.4) `EXECUTIVE_SUMMARY.md` ve `RISK_REGISTER.md`
  `docs/archive/`'a taşındı, ama `docs/VC_CHECKLIST_SCORE.md` içindeki
  kanıt tablosu hâlâ eski yolu (`docs/EXECUTIVE_SUMMARY.md`,
  `docs/RISK_REGISTER.md`) gösteriyor — yani sadeleştirme yeni kırık
  referans yarattı.
- **Yapılacak:**
  1. `docs/VC_CHECKLIST_SCORE.md` içinde geçen **her** `docs/XXX.md`
     dosya yolunu tara.
  2. Her biri için gerçek konumu kontrol et (`docs/`, `docs/archive/`,
     `docs/compliance/`, `docs/architecture/` olabilir).
  3. Yanlış olanları gerçek yola güncelle.
- **Yapılacak (otomatik tarama için):**
  ```bash
  grep -oE 'docs/[A-Za-z0-9_./-]+\.md' docs/VC_CHECKLIST_SCORE.md | sort -u | while read -r f; do
    test -f "$f" || echo "KIRIK: $f"
  done
  ```
- **Kabul kriteri:** Yukarıdaki komut **hiçbir "KIRIK:" satırı** döndürmemeli.

## MADDE 4 — Gerçek build/lint/test/deploy sonuçlarını dokümana ekle

- **Round 1'de ne yapıldı, neden yetersiz:** Hiç yapılmadı.
  `docs/VC_CHECKLIST_SCORE.md` hâlâ 2026-07-12 tarihli ve `%70.6` puanı
  hiç güncellenmemiş; hiçbir komut gerçekten çalıştırılıp loglanmamış.
- **Yapılacak:**
  ```bash
  npm ci                          2>&1 | tee /tmp/log-install.txt
  npm run typecheck                2>&1 | tee /tmp/log-typecheck.txt
  npm run lint                     2>&1 | tee /tmp/log-lint.txt
  npm run test                     2>&1 | tee /tmp/log-test.txt
  npm run build                    2>&1 | tee /tmp/log-build.txt
  npm --prefix backend ci          2>&1 | tee /tmp/log-backend-install.txt
  npm --prefix backend test        2>&1 | tee /tmp/log-backend-test.txt
  curl -I https://englishengineer.vercel.app                                    2>&1 | tee /tmp/log-vercel-health.txt
  curl -s https://englishengineer-production.up.railway.app/api/health          2>&1 | tee /tmp/log-railway-health.txt
  ```
  Bu 9 log dosyasının **tam çıktısını** (özetlenmemiş, kırpılmamış) yeni bir
  bölüm olarak `docs/VC_CHECKLIST_SCORE.md`'nin başına ekle:
  ```markdown
  ## Bağımsız Doğrulama Kaydı — <BUGÜNÜN TARİHİ>

  ### npm run typecheck
  ```
  <log içeriği>
  ```

  ### npm run lint
  ...
  ```
  Ardından genel puanı (`14120/20000` / `%70.6`) bu **gerçek** sonuçlara göre
  yeniden hesapla — test/build başarısızsa puanı düşür, geçiyorsa ilgili
  maddelerin kanıtını güncelle. Tahmini/iyimser puan yazma, sadece log'a
  dayalı puan yaz.
- **Kabul kriteri:** `docs/VC_CHECKLIST_SCORE.md` içinde gerçek komut
  çıktısı (hata mesajları dahil, varsa) görünür olmalı ve dosyanın
  `**Tarih:**` alanı bugünün tarihine güncellenmiş olmalı.
