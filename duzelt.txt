## Görev A — Gerçek bug: çeviri fallback mantığı (ÖNCELİK: Yüksek)

### Dosya
`src/shared/services/vocabulary-translation.service.ts`

### Mevcut kod (satır ~41-62)
```ts
export const resolveTermMeaning = (
  term: string,
  source: MeaningSource,
  language: string
): string => {
  const entry = cache?.[term.toLowerCase()];

  // 1. Try the corpus entry for the selected language (skip for English)
  if (language !== 'en') {
    const primary = entry?.[language]?.meaning;
    if (primary) return primary;
  }

  // 2. Turkish users: use the built-in turkishMeaning field
  if (language === 'tr') {
    if (source.turkishMeaning) return source.turkishMeaning;
  }

  // 3. For all other languages (de, ar, es, fr, etc.): show the English definition
  //    Do NOT fall back to Turkish — that would be confusing and incorrect.
  return source.definition || term;
};
```

### Sorun
Bu fonksiyon `language === 'tr'` DIŞINDAKİ tüm diller için `turkishMeaning` alanını **hiç kullanmıyor**
(kod yorumu bunun kasıtlı olduğunu söylüyor: "Do NOT fall back to Turkish"). Ama
`src/features/vocabulary/services/translation/vocabulary-translation.service.test.ts` dosyasındaki 3 test
tam tersini bekliyor — yani `turkishMeaning`'in, corpus'ta karşılık bulunamadığında **dil fark etmeksizin**
`definition`'dan ve ham terimden önce gelen bir fallback olmasını bekliyor:

```ts
// Test 1 — dil 'ar', hem turkishMeaning hem definition var → 'deneme' (turkishMeaning) bekleniyor,
// definition ('test') DEĞİL:
resolveTermMeaning('zzz-nonexistent-term', { turkishMeaning: 'deneme', definition: 'test' }, 'ar')
// mevcut kod 'test' döndürüyor (definition), test 'deneme' bekliyor → FAIL

// Test 2 — dil 'en', sadece turkishMeaning var, definition yok → 'kanca' bekleniyor:
resolveTermMeaning('zzz-hook-term', { turkishMeaning: 'kanca' }, 'en')
// mevcut kod ham terimi ('zzz-hook-term') döndürüyor → FAIL
```

### ⚠️ Karar gerektiren nokta — kör kör düzeltme yapma
Koddaki yorum satırı bu davranışın **kasıtlı bir ürün kararı** olduğunu söylüyor ("confusing and
incorrect" diye açıkça uyarıyor). Testler ise tam tersini talep ediyor. Bu iki şeyden biri doğru:

- **(a)** Yorum satırı doğru, testler eski/yanlış yazılmış → testleri düzelt, kodu OLDUĞU GİBİ bırak.
- **(b)** Testler doğru (yeni istenen davranış), kod güncellenmemiş → kodu düzelt, yorumu kaldır.

**Bu görevi yapan kişi/AI önce bunu netleştirmeli** (proje sahibine sor ya da ürün dokümanlarında —
`docs/PRODUCT.md`, `sonhal.md` — "Türkçe fallback" ile ilgili bir ürün kararı arayarak). Netleşmezse,
**varsayılan olarak (b)'yi uygula** — çünkü testler daha yeni yazılmış görünüyor ve `turkishMeaning`'in
tüm diller için "ham terimi göstermekten daha iyi" bir son çare olması ürün mantığına daha uygun (hiçbir
kullanıcı çıplak bir İngilizce terim görmek yerine Türkçe anlamı görmeyi tercih eder).

### Önerilen düzeltme (varsayım (b) uygulanırsa)
```ts
export const resolveTermMeaning = (
  term: string,
  source: MeaningSource,
  language: string
): string => {
  const entry = cache?.[term.toLowerCase()];

  // 1. Try the corpus entry for the selected language (skip for English)
  if (language !== 'en') {
    const primary = entry?.[language]?.meaning;
    if (primary) return primary;
  }

  // 2. Prefer the built-in turkishMeaning as a universal last-resort translation
  //    (better than showing the raw English term or a raw definition string).
  if (source.turkishMeaning) return source.turkishMeaning;

  // 3. Otherwise show the English definition if available.
  if (source.definition) return source.definition;

  // 4. Nothing to show — return the raw term.
  return term;
};
```

### Doğrulama
```bash
npx vitest run src/features/vocabulary/services/translation/vocabulary-translation.service.test.ts
```
6/6 test geçmeli. **Dikkat:** Bu dosyada `'never returns the corpus for English'` testi bazen
18+ saniye sürüyor (yavaş ama gerçek bir hata değil, corpus yükleme performansı — Görev C'ye bak).
Timeout hatası alırsan `vitest.config.ts`'deki `testTimeout` değerini kontrol et, gerekirse bu tek test
için `it('...', async () => {...}, 20000)` şeklinde süre uzat.

### Yan etki kontrolü
`resolveTermMeaning` başka yerlerde de çağrılıyor olabilir — düzeltmeden sonra global arama yap:
```bash
grep -rn "resolveTermMeaning" src/ --include="*.ts*" | grep -v ".test."
```
Her çağrı noktasında, `turkishMeaning`'in artık `definition`'dan önce öncelikli olmasının o ekranda
(örn. Almanca/Fransızca arayüzde) yanlış görünüp görünmeyeceğini kontrol et.

## Görev B — Test kokusu: landing page E2E testleri bayat metin arıyor (ÖNCELİK: Orta)

Bu **gerçek bir ürün hatası değil**. Landing page yeniden tasarlanmış ama testler eski tasarımın
metnini arıyor. İki dosyada aynı bayat referanslar var:

### Dosya 1: `src/e2e/critical-flows.e2e.test.tsx`
```ts
// SATIR 23 — mevcut (FAIL):
expect(screen.getAllByText(/Built for Engineers/i).length).toBeGreaterThan(0);
```
`"Built for Engineers"` metni artık `LandingPage/index.tsx`'te kullanılmıyor (o metin sadece
`src/pages/LandingPage/DisciplineShowcase.tsx` içinde, ve bu bileşen artık ana sayfada render edilmiyor).
Gerçek hero başlığı şu an `landing-i18n.ts`'ten geliyor: `heroBadge` alanı — örn. Türkçe için
`'EngineerOS • 10 Mühendislik Dalı × 15 Dil Desteği'`.

**Düzeltme:** Bu satırı, mevcut `heroBadge` metnine göre güncelle. En sağlam yol — metne değil,
`data-testid`'e bağlanmak (bkz. Görev B-ekstra aşağıda). Metne bağlanacaksan:
```ts
expect(screen.getAllByText(/EngineerOS/i).length).toBeGreaterThan(0);
```

```ts
// SATIR 33-40 — mevcut (FAIL: "shows 6 skill features on landing"):
it('shows 6 skill features on landing', () => {
  renderWithProviders(<LandingPage />);
  expect(screen.getByText(/Writing desk/i)).toBeInTheDocument();
  expect(screen.getByText(/Speaking room/i)).toBeInTheDocument();
  expect(screen.getByText(/Listening lab/i)).toBeInTheDocument();
  expect(screen.getByText(/Reading vault/i)).toBeInTheDocument();
  expect(screen.getByText(/Progress control/i)).toBeInTheDocument();
});
```
Gerçek kod (`LandingPage/index.tsx` satır ~278-289), `FEATURES` dizisindeki `key` alanını
`capitalize` CSS sınıfıyla render ediyor: `vocabulary`, `reading`, `writing`, `speaking`, `listening`,
`grammar` → ekranda "Vocabulary", "Reading", "Writing", "Speaking", "Listening", "Grammar" olarak görünür.
"Writing desk" / "Speaking room" gibi süslü isimler artık yok.

**Düzeltme:**
```ts
it('shows 6 skill features on landing', () => {
  renderWithProviders(<LandingPage />);
  expect(screen.getByText(/Vocabulary/i)).toBeInTheDocument();
  expect(screen.getByText(/Reading/i)).toBeInTheDocument();
  expect(screen.getByText(/Writing/i)).toBeInTheDocument();
  expect(screen.getByText(/Speaking/i)).toBeInTheDocument();
  expect(screen.getByText(/Listening/i)).toBeInTheDocument();
  expect(screen.getByText(/Grammar/i)).toBeInTheDocument();
});
```
(Not: `screen.getByText` birden fazla eşleşme varsa hata verir — "Reading"/"Writing" gibi kelimeler
sayfanın başka yerinde de geçiyorsa `getAllByText(...)[0]` kullan ya da `within()` ile FEATURES
bloğuna scope'la.)

### Dosya 2: `src/e2e/landing-page.e2e.test.tsx`
Aynı bayat referanslar (satır 24, 30-35) burada da var — **birebir aynı düzeltmeyi** bu dosyaya da uygula.
İki dosyanın aynı anda bozulmuş olması, muhtemelen bir kopyala-yapıştır kalıntısı; ileride tekrar
ayrışmasınlar diye bu iki testi tek bir paylaşılan yardımcı fonksiyona (`renderLandingAndGetFeatureLabels()`
gibi) taşımayı düşün.

### Görev B-ekstra (opsiyonel ama önerilir): testleri metne değil `data-testid`'e bağla
Metin bazlı testler UI kopyası her değiştiğinde tekrar kırılır (tam olarak bu görevin sebebi). Eğer
zaman varsa, `LandingPage/index.tsx`'teki hero ve feature bloklarına `data-testid="landing-hero"` ve
`data-testid={`landing-feature-${key}`}` gibi sabit testid'ler ekle, testleri bunlara göre yeniden yaz.
Bu, gelecekte metin/tasarım değiştiğinde testlerin kırılmasını önler.

### Doğrulama
```bash
npx vitest run src/e2e/critical-flows.e2e.test.tsx src/e2e/landing-page.e2e.test.tsx
```
Tüm testler geçmeli.
